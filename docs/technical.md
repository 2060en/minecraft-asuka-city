## 2. 建造原則：原汁原味

### 核心理念

盡量不使用任何模組與材質包，保持原版遊戲的樣貌。

### 可拔除原則

模組、材質包等外加內容，必須符合：

> **拔掉之後不影響體驗，放了錦上添花。**

### 自製附加內容：雙版本

專門為這個世界製作的附加內容採用雙版本（已定）：平常在使用自製方塊的「附加內容版」上建造，發布時用轉換程式把自製方塊換成指定的原版方塊，輸出「原味版」。主世界可以依賴自製的附加內容，但隨時都要能轉出完整的原味版；每一個自製的東西都要有好的原版替代，想不到就先不做。詳見[附加內容開發](addon.md)。

### 允許使用

遊戲本身提供的任何機制都可以使用，例如：

- 指令
- 作弊模式
- 結構方塊
- 其他遊戲內建功能

### 判斷準則（基岩版）

| 類型 | 移除後的影響 | 是否符合可拔除原則 |
| --- | --- | --- |
| 資源包（材質、音效、介面） | 只會回到原版外觀，世界內容不變 | 符合 |
| 行為包／附加元件（新增自訂方塊、實體、物品） | 自訂方塊會變成未知方塊，自訂實體與物品會消失 | 不符合 |
| 自製附加內容的自製方塊 | 主世界的自製方塊會變成未知方塊；原味版用轉換程式換成指定的原版方塊 | 符合（條件：每個自製方塊都有登記原版替代，見上方的雙版本） |
| 只含腳本的行為包（只把原版方塊換成另一個原版方塊） | 寫入的是原版資料，拔掉後不留任何東西 | 符合（見[附加內容開發](addon.md)） |
| 只讀取存檔的外部工具 | 不修改存檔，無影響 | 符合 |
| 寫入存檔的外部工具 | 視寫入內容而定：寫入的若是原版資料，工具移除後內容仍在 | 需逐一確認 |
| 實驗性功能 | 在基岩版中，一旦對世界開啟就無法關閉 | 不使用（見第 4 節） |

| 項目 | 內容 |
| --- | --- |
| 世界名稱 | 待補 |
| 世界類型 | 無限 |
| 種子碼 | 已不重要（見下方說明） |

| 實驗性功能 | 未開啟 |

### 種子碼為什麼不重要

1. 都市以外的地形已經被 WorldPainter 製作的自訂地形取代（見第 7 節），原本由種子生成的地形只剩自訂地圖範圍外的部分。
2. 基岩版 1.18（洞穴與山崖更新第二部分）改寫了地形生成，同一個種子在 1.18 前後生成的地形完全不同。已經生成過的區塊不會改變，只有新區塊會用新規則生成。

### 實驗性功能事件

曾經對世界開啟過實驗性功能，開啟後無法再關閉，結果出現相容性問題，最後靠備份還原。

**教訓：** 不要對正式世界開啟實驗性功能。如果想試用，先複製一份世界，在副本上測試。

### 遊戲規則

建造時使用創造模式，遊戲規則對建造影響不大，可以隨時調整，因此不逐一記錄。目前的習慣是：

- 大部分時間固定白天，要看燈光效果時用指令切到晚上
- 火不會蔓延
- 生物不會掉落物品
- 方塊、實體不會掉落物品（`doTileDrops`、`doEntityDrops` 關閉，主世界與測試世界的存檔都是，2026-11-05 查到）

世界內設有用指令方塊切換這些設定的世界控制室，位在總部地堡，見[總部地堡](world/bunker.md#總指揮)。新玩家的出生點與開場橋段見[新玩家序章](prologue.md)。

## 5. 結構方塊

建造時經常使用結構方塊來輔助。

### 基本資訊

- 取得方式：`/give @s structure_block`
- 單一結構的大小上限：64 × 384 × 64（X × Y × Z），超過 64 格寬的建築需要拆成多段儲存
- 指令替代方式：
  - 儲存：`/structure save <名稱> <起點座標> <終點座標>`
  - 載入：`/structure load <名稱> <放置座標>`
- 儲存位置：用結構方塊儲存的結構存在世界存檔內部，不是獨立檔案，只能用名稱叫出來

### 使用方式：當作快取

結構方塊主要當作「快取」使用，很少長期保存完整命名的結構。

| 名稱 | 用途 |
| --- | --- |
| `r` | 主要快取。要重複建造某個結構時，先蓋一個並存成 `r`，然後重複放置。換下一個結構時，同樣覆蓋存成 `r`。選 `r` 是因為離食指近 |
| `e` | 次要快取，偶爾需要同時暫存兩個結構時使用 |
| `r1`、`r2`、`r3`… | 結構超過大小上限、需要拆段儲存時使用 |

因為快取名稱會被反覆覆蓋，存檔內累積的結構數量很少。

### UWP 與 GDK

Windows 基岩版在 2025 年底從 UWP 版本改為 GDK 版本，存檔位置跟著變動：

- 舊位置（UWP）：`%LOCALAPPDATA%\Packages\Microsoft.MinecraftUWP_8wekyb3d8bbwe\LocalState\games\com.mojang\minecraftWorlds`
- 新位置（GDK）：`%APPDATA%\Minecraft Bedrock\Users\<使用者編號>\games\com.mojang\minecraftWorlds`

新位置的存檔放在 `Users\<使用者編號>` 底下，跟登入的帳號綁在一起：換帳號登入時會看不到這個世界，備份時也要確認備份的是正確帳號底下的資料夾。

### 備份方案（已實測，2026-11-05）

使用方式、還原、電腦壞掉時怎麼辦、設定步驟都在 [`tools/world-backup`](../tools/world-backup/README.md)。每次備份的紀錄在 [`backup-log.md`](backup-log.md)。

#### 已決定

| 項目 | 決定 |
| --- | --- |
| 存放位置 | Google Drive（5 TB 空間）的 `minecraft-backup` 資料夾，restic 加密，在 Google Drive 上看不到內容 |
| 執行方式 | 手動雙擊 `backup.bat`（遊玩時間不固定，不排程） |
| 備份工具 | restic，透過 rclone 連 Google Drive |
| Google 憑證 | 用作者自己的 Google Cloud 專案 `asuka-backup`，因為 rclone 內建的共用憑證 2026 年內會停用（作者決定，2026-11-05）。Google 要求發布前填首頁和隱私權政策，放在公開的小頁面 [asuka-backup-app](https://github.com/2060en/asuka-backup-app) |
| Google 權限 | `drive.file`：rclone 只能碰自己建立的檔案，看不到 Google Drive 裡的其他東西 |
| 密碼 | 作者自己想的，放在 repo 外面（`%USERPROFILE%\.config\asuka\restic-password.txt`），作者另外存一份。弄丟就永遠打不開備份 |
| 和雲端地圖的關係 | 分兩段：先做備份，再接雲端地圖（作者決定，2026-11-05）；兩段都已完成，同一次雙擊一起做 |

#### 流程

雙擊 `backup.bat` 執行：

1. 確認 Minecraft 已關閉，開著就不備份，避免備份到寫入中的檔案
2. 用 restic（透過 rclone）對世界資料夾建立快照，只存有變動的部分。只讀取世界，不寫入
3. 依保留規則清理過舊的快照（規則待決定，目前全部保留）
4. 用 uNmINeD 渲染網頁地圖、把有變動的圖磚上傳到 Cloudflare R2（見下方「雲端地圖」）。這段失敗時世界還是備份好了，下次會一起補上
5. 把紀錄（日期、備註、世界大小、新增大小、地圖）寫入這個 repo 的 `docs/backup-log.md`

還原用 `restore.bat`：只還原到新的資料夾，不碰世界資料夾，還原完和目前的世界逐檔比對。

#### 待討論

- 只用 restic，或 restic 與 Kopia 並行
- restic 快照的保留規則（例如每天保留 7 份、每月保留 24 份）。目前全部保留，世界約 1 GB、空間 5 TB，不急。實測只是開遊戲放幾個方塊，備份就增加 182～261 MB（遊戲開關時 LevelDB 會重整檔案）
- 是否定期另外匯出 `.mcworld`，當作不依賴備份工具的獨立副本
- 開發備份小程式：建造 dashboard、比較各版本鳥瞰圖的差異
- 把規劃圖和最新鳥瞰圖疊在一起比對，追蹤規劃的完成度

### 雲端地圖（已接上，2026-11-05）

#### 需求（作者提出）

- 隨時隨地、用手機也能查看世界地圖的全貌，像是雲端版的 uNmINeD
- 世界存檔只在筆電裡，筆電關機時物理上讀不到，所以雲端能看到**定期備份時的地圖**就夠了，包括最新一次備份

#### 做法（已定）

重點是**不在雲端讀原始存檔**，而是在備份時（筆電開著、Minecraft 已關閉）順便把地圖畫好，只把畫好的地圖傳上雲端：

- 雲端要讀存檔（LevelDB 資料庫），得先從備份還原整份存檔、再跑渲染程式，需要一台雲端主機，費用和維護都高
- 手機上看的是網頁地圖（圖磚加上檢視網頁），不管怎樣都要先渲染；渲染只要在備份時做一次

流程：

1. 備份腳本建立 restic 快照之後，執行 `unmined-cli web render` 輸出網頁地圖。每次都全部重畫（uNmINeD 判斷有沒有變動時看不到最新的改動，見下方的問題表）
2. 把網頁地圖上傳到雲端，只傳有變動的圖磚
3. 手機打開網址就能看；網頁裡可以切換不同備份日期的地圖

實測量體（2026-11-05 第一次渲染）：自訂地圖約 15360 × 13312 格（之前估的 8000 × 8000 不對），全世界 102 萬個區塊，WebP 無損圖磚 4540 張、內容相同的只存一份後 54 MB。第一次渲染 58 秒、上傳 2 分 8 秒，之後每次全部重畫：無影子約 1～3 分鐘，開 3d 影子約 4 分 20 秒（只測過一次）。圖磚在各次備份之間共用，實測放一小塊方塊只多傳 7 張、不到 1 MB；改外觀時才會整份重傳（52 MB）。R2 免費額度 10 GB，目前用 107 MB。

世界裡除了主體（X -7680～11264，Z -10240～11264），還有幾塊遠處的零星區域，應該是以前飛過或傳送時留下的，最遠到世界邊界 (-30000000, 30000000)：(90368, 28416) 附近、(-99840, 99840)、(-999936, 999936)、(9984, 99840)。地圖只把主體當成預設範圍，這些區域還是看得到。

實際接上時遇到、已經處理的問題：

## 8. 待辦與構想

### 查明世界大小的組成

世界接近 2 GB，需要確認空間主要被什麼佔用。目前推測：

- **自訂地形（可能性最高）**：WorldPainter 地圖範圍內的區塊在合併時就全部寫進存檔，不像原版地形是飛到哪才生成到哪。8000 × 8000 格約為 25 萬個區塊，平均每個區塊約 8 KB，量級和 2 GB 相符
- **自訂地圖範圍外飛過的區塊**：原版地形，載入過就會永久存下
- **內嵌在世界資料夾裡的資源包或行為包**
- 結構方塊與地圖畫：數量少，不太可能是主因

### 處理自訂地圖範圍外的地形

希望把自訂地圖範圍以外的原始地形「剪掉」，或改成無限的海。非必要，有方法再做。

可能的做法（待驗證，先在副本上測試）：

1. 用 Amulet 的 Prune Chunks 刪掉自訂地圖範圍以外的所有區塊
2. 修改世界的 `level.dat`，把地形生成器改成「平坦」，並把平坦層設定成海床加海水

已經生成的區塊（都市與自訂地形）不受影響，之後才生成的新區塊會變成一望無際的平坦海洋。海水高度要跟自訂地圖的海平面一致，交界處的海面才會接得起來。

### NPC 會轉頭看玩家（暫不做）

想讓 NPC 完全定格、不轉頭，但原版做不到。作者決定暫時不做下面的行為包（2026-11-03），研究內容留著，之後要做時參考。

**原因（已確認）：** 原版 NPC（`minecraft:npc`）的實體定義裡有 `minecraft:behavior.look_at_player`：玩家進入 6 格內時，會不定時轉頭看玩家 1～2 秒。NPC 沒有任何走動的行為，所以本來就不會自己走開，會動的只有頭。基岩版沒有 Java 版的 `NoAI`，指令關不掉這個行為。來源：Mojang 官方的 [bedrock-samples](https://github.com/Mojang/bedrock-samples) 中的 `behavior_pack/entities/npc.json`（1.26.60）。

**原版指令的極限：**

- 重複型指令方塊每刻 `/tp` 鎖角度：會和 AI 互搶，頭照樣轉（實測無效）
- 騎乘盔甲座：盔甲座不可搭乘（實測）。就算騎上其他載具，定義裡也沒有「騎乘時不看玩家」的條件
- 緩速效果：只影響移動，不影響轉頭
- 唯一的原版緩解：玩家離 NPC 超過 6 格就不會轉頭，例如放在舞台、陽台等玩家靠不近的位置

**可行方案：** 只修改原版 NPC 的行為包，把 `look_at_player` 刪掉。不新增任何方塊、實體或物品，不需要開實驗性功能；停用後 NPC 只是恢復轉頭，世界內容不變。效果套用到世界裡所有的 NPC。

**製作方式：** 複製 bedrock-samples 的 `npc.json`，只刪掉 `minecraft:behavior.look_at_player`。遊戲更新如果改了 NPC 的定義（例如新增造型），要用新版的原版檔重做一次，否則新內容會被舊定義蓋掉。

**之後要做時再決定：**

- 這種「只刪原版行為、不新增內容」的行為包，算不算符合第 2 節的可拔除原則
- 要不要把行為包的原始檔也放進這個 repo 管理
