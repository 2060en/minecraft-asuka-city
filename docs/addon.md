# 附加內容開發

記錄專門為這個世界製作的附加內容（資源包＋行為包）：目標、做法、基岩版的技術限制與構想清單。

> 技術面的說明以 2026 年 10 月的基岩版（1.26.60 前後）為準，標記「待實測」的要在遊戲裡確認。Claude 提出的做法在作者同意前都是「待決定」，選項整理在最後的[待決定事項](#待決定事項)。

---

## 1. 目標與方向

### 目標（已定）

- 做一套專門給這個世界用的附加內容，資源包與行為包一體
- 想到什麼、需要什麼才加，會一直持續添加
- 不能違反[可拔除原則](technical.md#2-建造原則原汁原味)：拔掉之後不影響體驗，放了錦上添花
- 作者最初的構想：原本是「某類」東西的原版方塊，用魔法棒點擊才變成自製的樣子；拔掉附加內容後，它還是原本那類的原版方塊

### 作者的顧慮：拔掉後的外觀

第一版提案是「載體方塊」（見[曾考慮的做法](#曾考慮的做法載體方塊)）：例如玻璃地板門其實是上蠟的銅地板門，拔掉附加內容就顯示成銅地板門。作者指出這樣拔掉後外觀差太多，一樣違反原則。

原版本來就顯示不出新外觀，任何新外觀拔掉後都一定會變樣，差別只在「變成什麼」。載體方塊的問題是退路被載體綁死，不是作者在原版時會選的東西。

### 雙版本（已定）

作者提出的做法：

- 主要在**附加內容版**上建造
- 發布時，用轉換程式找出整張地圖的自製方塊，換成指定的原版方塊，輸出**原味版**
- 可拔除原則的意義跟著改變：主世界可以依賴附加內容，但隨時都要能轉出完整的原味版

就像程式的原始碼與編譯產物：附加內容版是唯一的原始版本，原味版是轉換出來的，不另外維護。

### 原版替代的準則（已定）

**每一個自製的東西，都要有好的原版替代；想不到好的原版替代，就先不做**，放進[暫緩](#42-暫緩)。

例如更立體的鐵軌、換成燈飾的烽火台與螢光石，都是因為還想不到好的原版替代而暫緩。原版替代也可以是「不顯示」，例如咖啡杯。

## 2. 做法

### 三種東西分開處理

| 類型 | 例子 | 原味版怎麼來 |
| --- | --- | --- |
| 自製方塊（行為包＋資源包） | 單色門、單色地板門、傳送履帶的機身、外帶咖啡杯 | 轉換程式換成對照的原版方塊 |
| 原版東西換材質（只用資源包） | 物品框架、發光物品框架、畫、NPC 皮膚、界伏蚌盒、漏斗、終界燭的粒子 | 不用轉換：拿掉資源包就是原版的樣子 |
| 原版功能 | Image map 做的地圖畫 | 兩個版本完全一樣 |

### 對照表

每一種自製方塊都要登記一個原版對照（包含方向、開關等狀態怎麼對應），寫成一個檔案放在 repo 裡。轉換程式、魔法棒、這份文件都以這張表為準。

**規則：沒有登記對照的自製方塊，不能放進世界。** 對照在做出方塊的當下就決定，不要等到發布時才回頭想。

對照也可以是空氣，也就是原味版裡直接不顯示。適合小型擺飾，例如咖啡杯（已定）。

### 轉換程式（提案，待決定）

- 在遊戲外處理存檔的**副本**，主世界不動
- 遊戲內的腳本只能讀寫已載入的區塊，8000 × 8000 格的地圖不適合在遊戲裡逐格掃描
- 基岩版的存檔把每 16 × 16 × 16 格的區段存成「調色盤＋索引」：區段裡用到哪幾種方塊列在調色盤，每一格只記編號。所以只要把調色盤裡的自製方塊換成對照的原版方塊就好，不用逐格處理，整張地圖也很快；用結構方塊、`/fill` 放的方塊一樣抓得到
- 遇到對照表沒有的自製方塊就停下來報錯，避免漏掉的方塊在原味版變成未知方塊
- 對照到有方塊實體的原版方塊時，要一併補上方塊實體的資料（待實測）
- 工具：自己寫（放在這個 repo），或用作者用過的 Amulet（對新版存檔的支援程度待確認）
- **不要等到發布才寫**：附加內容哪天壞掉時，它是退路。建議和[備份](technical.md#6-存檔與備份)一起跑，每次確認轉出來的原味版打得開、沒有未知方塊

### 魔法棒（選用，待決定）

- 自製方塊可以直接從物品欄拿出來放，魔法棒不是必要的
- 用途：把世界裡已經蓋好的原版門、地板門，原地換成單色門、單色地板門，保留方向與開關
- 用原版物品當魔法棒，拔掉行為包後只是變回普通物品

### 風險

| 風險 | 對策 |
| --- | --- |
| 遊戲自動更新後附加內容壞掉，主世界的自製方塊變成未知方塊 | 已知的行為是資料會保留、附加內容修好後恢復（待實測，要最先測）；大更新前先備份；只用穩定版的功能，不開實驗性功能 |
| 自製物品或實體放進世界（例如放進箱子、物品框架） | 原則上世界裡只放自製方塊，不放自製物品與實體 |
| 結構方塊存起來的結構裡有自製方塊 | 結構只當快取用（見[技術文檔第 5 節](technical.md#5-結構方塊)），原味版不需要 |

## 3. 基岩版的技術限制

| 項目 | 說明 |
| --- | --- |
| 資源包只能換原版方塊的材質，不能換形狀 | 原版方塊的形狀寫死在遊戲裡：門還是門的形狀，漏斗還是漏斗的形狀 |
| 原版方塊換材質是整種一起換 | 同一種方塊沒辦法這格換、那格不換，也不能依方向、開關等狀態換不同的圖 |
| 自製方塊能做的事 | 自己的形狀（模型）、半透明、動畫、發光、方向與開關等狀態。門與地板門的開關、兩格高的門、點擊增加個數、對紅石訊號的反應，都要另外寫腳本（穩定版的 Script API 能不能讀到紅石訊號，待確認） |
| 自製方塊拔掉後 | 變成未知方塊，自製物品與實體會消失 |
| 腳本 | 只用穩定版的 Script API，不用需要開啟實驗性功能（Beta API）的部分，見[技術文檔第 4 節](technical.md#實驗性功能事件)的教訓 |

查原版的材質檔名、方塊狀態時，以 Mojang 官方公開的原版資源包與行為包為準：<https://github.com/Mojang/bedrock-samples>

## 4. 構想清單

構想都是作者提出的，作者在 2026-10-31 逐項確認過。

### 4.1 要做

| 構想 | 附加內容版 | 原味版 | 備註 |
| --- | --- | --- | --- |
| 單色地板門（淺灰、白） | 自製方塊，形狀和原版地板門一樣。外觀定稿：素面加一圈細框，沒有把手（已定）。草稿見 `addon/drafts/doors/` | 杉木地板門 | 功能要和原版的杉木地板門一樣（已定）：點擊開關、紅石訊號開關、放在上半或下半格。原味版保留方向、上下與開關狀態 |
| 單色門（淺灰、白） | 自製方塊（上下兩格），形狀和原版門一樣。外觀定稿：淺灰、白兩色，邊緣一圈稍深的細框，兩面都畫上拉桿式門把（平面，不做立體）（已定）。草稿見 `addon/drafts/doors/` | 杉木門 | 廁所隔間門用淺灰。功能要和原版的杉木門一樣（已定）：點擊開關、紅石訊號開關、門軸左右、並排放時自動成對、開著時碰撞範圍跟著變。原味版保留方向、門軸與開關狀態。是最費工的一項 |
| 傳送履帶 | 上面放原版的普通軌道，下面墊自製的「履帶機身」方塊；機身的模型往上長，把鐵軌蓋住，看起來就是履帶（已定，2026-11-01）。履帶的外觀定稿：靜止不動，黑色橡膠履帶厚 2 像素，兩側有高出 1 像素的鋼製護欄，寬度佔滿一格；有直線、彎道、斜坡三種形狀，尾端不另外收邊（已定）。機身只做金屬灰一種（已定）。草稿見 `addon/drafts/conveyor/` | 機身換成煤炭方塊（已定），鐵軌不動 | 見下方「傳送履帶的做法」 |
| 動力版傳送履帶 | 同一個機身，上面改放原版的動力軌道；護欄側面多一條黃線，方便分辨（已定）。動力軌道通電時黃線變亮（暫定，跟著原版動力軌道的功能） | 同上 | 動力軌道不能轉彎，所以只有直線與斜坡 |
| 外帶咖啡杯 | 自製方塊。像海鞘、蠟燭一樣，拿杯子對它點擊，可以從 1 個增加到 4 個，每個杯子的大小不變。外觀定稿：白色杯身、牛皮紙杯套、白色杯蓋，大小與 1～4 杯的排列照草稿（`addon/drafts/coffee_cup/`） | 不顯示 | 個數記在方塊的狀態裡，點擊增加用腳本處理。桌面是全方塊、上半磚或上半的地板門時，杯子剛好放在桌面上；桌面是下半磚的話會浮起半格（待實測） |
| 白色的物品展示框，兼當萬用盤子 | 物品框架整種換成白色；平放在桌面上，放進食物就是一盤菜 | 原版物品框架 | 已經放著地圖畫的一般框也會一起變白（作者確認沒問題）。盤子是方的 |

| 電腦螢幕 | 一格高的畫換成電腦螢幕 | 原版的畫 | 原版 1×1 的畫至少有 7 幅，全部做成電腦螢幕的話，隨機到哪一幅都是螢幕。做成立體的自製方塊沒有好的原版替代，所以用畫 |
| NPC 皮膚 | 原版 NPC（`/summon npc`）的皮膚換掉 | 原版 NPC 的皮膚 | 原版有 60 種皮膚可以換，分成科學家、老師、建築工人、農夫、商人等職業；按職業對應替換，原味版也還是同一種職業。NPC 不會走動，可以設定對話 |
| 終界燭不要有粒子效果 | 資源包把終界燭的粒子改成不顯示 | 原版終界燭（有粒子） | 粒子效果是資源包可以改的檔案，所有終界燭一起變（待實測） |
| 界伏蚌盒 → 置物櫃 | 資源包只把白色界伏蚌盒換成鐵製置物櫃，車站、機場會出現的那種。草稿：白色鋼板門、左上角號碼牌、右側投幣鎖（投幣孔、鑰匙孔、紅色使用中燈）、左下通風孔，門與門之間有灰色接縫。界伏蚌盒放在地上時方向固定，看得到哪一面取決於牆的方向，所以四個側面都畫門；排成一排時，兩端的側面也會是門。草稿見 `addon/drafts/locker/` | 原版白色界伏蚌盒 | 作者的界伏蚌盒只拿來當置物櫃，原則上只用白色。一樣能放東西，一格一個，疊起來就是一整排置物櫃。打開時蓋子往上掀的動作改不了（待實測）。界伏蚌（生物）和界伏蚌盒共用材質，但只換白色的話，只有被染成白色的界伏蚌會受影響，可以忽略 |
| 漏斗 → 小便斗 | 資源包把漏斗整種換成灰白色 | 原版漏斗 | 不另外做自製的小便斗 |

#### 傳送履帶的做法

作者要求功能和原版鐵軌一樣（已定）。自製方塊沒辦法當鐵軌：礦車沿著鐵軌走的規則寫死在遊戲裡，只認原版的四種鐵軌，基岩版的自製方塊沒有「當作鐵軌」的設定。所以採用以下做法（已定，2026-11-01）：

- **鐵軌是真的原版鐵軌**，礦車、動力軌道加速、自動接成彎道與斜坡，全部照原版
- **下面那格是自製的履帶機身**，是一個完整的方塊，模型再往上長 3 像素，畫出履帶與護欄，把鐵軌蓋住。礦車看起來會陷進履帶 1～2 像素
- **腳本**讀上面鐵軌的方向、種類（普通或動力）與通電狀態，切換機身要畫的履帶形狀與黃線；上面沒有鐵軌時，只顯示機身
- **斜坡分兩段畫**：自製方塊的模型最高只能到 30 像素，下面的機身只能畫到斜坡的大約三分之二，剩下的上半段由斜坡頂端那一格的機身往外畫補上。所以斜坡頂端接的那一格也必須是機身方塊，否則會露出一小段原版鐵軌。補的那一段會往旁邊那格伸出約 6 像素，自製方塊的模型能不能往旁邊伸這麼多，待實測
- **原味版**：機身換成煤炭方塊（已定），鐵軌本來就是原版的，不用動

其他考慮過的做法（不採用）：

| 做法 | 內容 | 不採用的原因 |
| --- | --- | --- |
| 履帶做成自製方塊、取代鐵軌 | 第一版草稿的做法 | 礦車不能跑 |
| 用腳本推礦車 | 履帶維持自製方塊，腳本每一刻把上面的礦車往前推 | 只是模擬，轉彎、爬坡、加速都不會真的和原版一樣，礦車也不能直接放在自製方塊上 |

### 4.2 暫緩

還想不到好的原版替代，先放著，想到再做。

| 構想 | 原因與備註 |
| --- | --- |
| 更立體、更真實的特色鐵軌 | 還想不到原版替代。另外要先確認現有的鐵路軌道在原版是怎麼蓋的：原版軌道只有 1 格寬，相當於約 1 公尺的軌距，照[比例尺](scale.md)的微觀放大原則，主線鐵路的軌距應該在 2 格左右 |
| 烽火台、螢光石換成燈飾 | 原味版會直接顯示成烽火台、螢光石，不是好的原版替代 |
| 菌光體（作者寫的「俊光體」）換成燈飾 | 作者確認清單時沒有提到，先和烽火台、螢光石一起暫緩 |
| 自製燈具 | 還想不到好的原版替代 |

### 4.3 不做

| 構想 | 原因 |
| --- | --- |
| 玻璃門、玻璃地板門 | 作者決定不用 |
| 自製的小便斗 | 改成漏斗換材質就好 |

## 5. 開發方式（提案，待決定）

- **原始檔放在這個 repo**：資源包、行為包、對照表、轉換程式都放在 repo，每加一個東西就 commit，修改紀錄都留著
- **開發用資料夾**：用 Windows 的目錄連結（junction），把 repo 裡的資料夾連到遊戲的 `development_resource_packs` 與 `development_behavior_packs`。放在開發用資料夾的包不會被遊戲快取，改完重新進入世界就生效，不用每次改版本號；腳本可以用 `/reload` 重新載入。GDK 版的資料夾位置待確認（UWP 版在 `...\LocalState\games\com.mojang\` 底下）
- **只掛在這個世界上**：不全域啟用，其他世界不受影響
- **材質解析度**：作者近期沒有用其他材質包，自製材質照原版的 16x 畫（1 格 16 像素）
- **先在副本上測試**：新東西先在世界副本上試，穩定後才套用到正式世界
- **封存**：穩定的版本打包成 `.mcaddon` 存一份，換電腦或備份時用
- **工具**：材質用像素繪圖軟體畫；自製方塊的形狀用 Blockbench 做

### 外觀設計流程（暫定）

外觀直接在和 Claude 的對話裡討論：

1. Claude 把每一個東西的草稿放在 `addon/drafts/<名稱>/`：`build.py` 產生基岩版的模型檔（`.geo.json`）與材質（`.png`），`preview.json` 設定要看的角度
2. 用 `tools/preview/` 的預覽工具（three.js 加無頭瀏覽器）算出預覽圖 `preview.png`，傳給作者看
3. 作者提意見，Claude 修改後重新算圖；作者也可以用 Blockbench 打開同一份 `.geo.json` 自己轉著看或修改
4. 定稿後再搬進正式的資源包與行為包

## 6. 研究：盾牌與旗幟的自訂圖案

作者問：有沒有像 Image map 一樣的外部工具，可以設定盾牌的圖案？了解以下方法後，作者決定**先不做**（2026-10-31）。

**沒有像 Image map 那樣能放任意圖片的工具。** 地圖畫在存檔裡存的是每一格像素的顏色，所以外部工具可以寫進任何圖片；盾牌和旗幟存的只是「底色＋幾層（圖案形狀、顏色）」，形狀只能從原版既有的圖案裡挑，沒有存像素的地方。

可行的方法：

| 方法 | 做法 | 限制 | 原味版 |
| --- | --- | --- | --- |
| 原版旗幟圖案 | 用織布機把圖案疊在旗幟上，再和盾牌合成。網路上有旗幟設計工具，可以先排好要疊哪幾層 | 只能用原版的形狀，織布機最多疊 6 層 | 一樣 |
| 外部工具改物品資料 | 用 NBT 編輯工具直接寫進超過 6 層的圖案 | 形狀一樣只能用原版的；超過 6 層能不能正常顯示，待實測 | 一樣 |
| 資源包換掉旗幟圖案的形狀 | 把平常用不到的特殊圖案（例如 Mojang 標誌、地球、苦力怕、頭顱、花朵、豬布林鼻子）換成自己的形狀，例如國徽、公司標誌。每一層是一個顏色，多色的標誌拆成幾層疊起來。旗幟與盾牌都適用 | 每一層只有一個顏色，最多 6 層；換掉後所有用到那個圖案的旗幟都會變。如果圖案的上色方式是相乘，畫成彩色、用白色染料套上去就能一層顯示全彩，待實測 | 顯示原本的圖案（例如地球），要判斷算不算好的原版替代 |
| 資源包換掉盾牌本身的材質 | 直接畫一張全彩的盾牌，例如警察的鎮暴盾牌 | 所有沒套旗幟的盾牌都會變成同一個樣子 | 原版的木頭盾牌 |
| 地圖畫 | 如果只是想把標誌掛在牆上，用 Image map 做地圖畫放進物品框架 | 不是盾牌的形狀 | 一樣 |

## 曾考慮的做法：載體方塊

每一種自製外觀配一種平常用不到的原版方塊當「載體」，資源包只換載體的材質，魔法棒把點到的方塊換成載體。例如上蠟的銅地板門在原版和未上蠟的長得一樣，改掉也不損失原版外觀，可以當玻璃地板門的載體。

- 優點：主世界不依賴附加內容，拔掉後不會出現未知方塊，也不需要轉換程式
- 缺點：拔掉後顯示成載體（例如銅門），外觀差太多；只能換材質，做不出新形狀；原版方塊換材質是整種一起換
- 結果：作者認為拔掉後的外觀違反原則，不採用
