# 附加內容開發

記錄專門為這個世界製作的附加內容（資源包＋行為包）：目標、基岩版的技術限制、做法與構想清單。

> 技術面的說明以 2026 年 10 月的基岩版（1.26.60 前後）為準，標記「待實測」的要在遊戲裡確認。Claude 提出的做法在作者同意前都是「待決定」，選項整理在最後的[待決定事項](#待決定事項)。

---

## 1. 目標（已定）

- 做一套專門給這個世界用的附加內容，資源包與行為包一體
- 想到什麼、需要什麼才加，會一直持續添加
- 必須符合[可拔除原則](technical.md#2-建造原則原汁原味)：拔掉之後不影響體驗，放了錦上添花
- 平常用不到的醜方塊，可以拿來換成自己需要的東西
- **轉換機制（作者的構想）**：原本是「某類」東西的原版方塊，判斷確實是那類東西，用魔法棒點擊才變成自製的樣子；拔掉附加內容後，它還是原本那類的原版方塊。例如對漏斗點擊會變成小便斗，拔掉後還是漏斗

## 2. 基岩版的技術限制

這些限制決定了能怎麼做。

| 項目 | 說明 |
| --- | --- |
| 資源包只能換材質，不能換形狀 | 原版方塊的形狀寫死在遊戲裡：門還是門的形狀，漏斗還是漏斗的形狀，資源包只能改貼在上面的圖 |
| 換材質是整種一起換 | 同一種方塊沒辦法這格換、那格不換，也不能依方向、開關等狀態換不同的圖。只有遊戲本身就分開的部分可以分開換，例如軌道的直線與彎道、觸發軌道的充能與未充能 |
| 可以讓一種方塊改用新的材質檔 | 不必動到共用的材質檔。例如烽火台的外殼原本共用玻璃的材質，可以只改烽火台而不動玻璃 |
| 方塊動畫 | 資源包可以讓原版方塊的材質變成動畫，像水和岩漿那樣 |
| 自訂方塊、物品、實體 | 拔掉行為包後，自訂方塊變成未知方塊，自訂物品與實體消失 → 不符合可拔除原則 |
| 行為包的腳本 | 腳本如果只是把原版方塊換成另一個原版方塊，寫進存檔的仍是原版資料，拔掉後不留任何東西 → 符合，性質和寫入原版資料的外部工具（Amulet、Image map）相同 |
| 實驗性功能 | 腳本只用穩定版的 Script API，不用需要開啟實驗性功能（Beta API）的部分，見[技術文檔第 4 節](technical.md#實驗性功能事件)的教訓 |

查原版的材質檔名、方塊狀態時，以 Mojang 官方公開的原版資源包與行為包為準：<https://github.com/Mojang/bedrock-samples>

## 3. 做法：載體方塊

「只能整種換材質」加上「不能用自訂方塊」，要做到「點了才變、拔掉復原」，做法只有一種：

1. 每一種自製外觀，配一種平常不會用到的原版方塊當**載體**，資源包把載體的材質換掉
2. 魔法棒只做一件事：把點到的方塊換成同一類的載體方塊，保留方向、開關等狀態
3. 拔掉資源包：載體顯示原版的樣子，仍是同一類東西（門還是門）
4. 拔掉行為包：魔法棒失效，已經換好的方塊不受影響

整種方塊都用不到的時候（例如螢光石），直接換材質就好，不需要魔法棒。

### 上蠟的銅：不損失原版外觀的載體

上蠟和未上蠟的銅門、銅地板門，在原版共用同一張材質，長得一模一樣。資源包可以只讓上蠟的版本改用新材質，未上蠟的仍然是銅的樣子，原版的外觀一個都沒有少。銅門與銅地板門各有 4 種上蠟版本（原色、外露、風化、氧化），各可以當 4 種載體。

代價：之後要蓋銅門，只能用未上蠟的。未上蠟的銅會隨時間氧化，完全氧化後就不再變。

### 載體登記表

每一種載體只能對應一種自製外觀。第 4 節的表確定後就是登記表，新增項目前先查表，避免兩個東西搶同一個載體。

## 4. 構想清單與可行性

構想是作者提出的；「載體與做法」是 Claude 的提案，狀態都是待決定。

| 作者的構想 | 載體與做法 | 拔掉資源包後 | 可行性與限制 |
| --- | --- | --- | --- |
| 地板門（任何）→ 玻璃地板門 | 魔法棒換成上蠟的銅地板門（`waxed_copper_trapdoor`） | 銅地板門 | 可行。玻璃大概只能做「中間挖空、留框」的全透明，做不出半透明（待實測） |
| 地板門（任何）→ 淺灰地板門 | 魔法棒換成上蠟的外露銅地板門 | 銅地板門 | 可行 |
| 地板門（任何）→ 白色地板門 | 魔法棒換成上蠟的風化銅地板門 | 銅地板門 | 可行。上蠟的氧化銅地板門先保留 |
| 門（任何）→ 玻璃門 | 魔法棒換成上蠟的銅門（`waxed_copper_door`），上下兩格一起換 | 銅門 | 同玻璃地板門 |
| 門（任何）→ 淺灰門 | 魔法棒換成上蠟的外露銅門 | 銅門 | 可行。廁所隔間門用這個 |
| 門（任何）→ 白色門 | 魔法棒換成上蠟的風化銅門 | 銅門 | 可行。上蠟的氧化銅門先保留 |
| 鐵軌 → 傳送履帶 | 魔法棒換成觸發軌道（`activator_rail`）。未充能時靜止，充能時是會動的動畫 | 觸發軌道 | 可行。只能直線與斜坡，不能轉彎（原版只有普通軌道能轉彎），行李轉盤的彎道做不出來 |
| 鐵軌 → 更立體、更真實的特色鐵軌 | 普通軌道（`rail`）整種換材質 | 普通軌道 | 只能做「畫出立體感」的平面貼圖，軌道本身是平的。真正立體要用自訂實體疊在軌道上：拔掉後實體消失、軌道還在，符合原則，但數量一多會卡，只適合短距離展示 |
| 物品展示框 → 白色的框 | 物品框架（`frame`）整種換材質 | 原版物品框架 | 可行。已經放著地圖畫的一般框也會一起變白 |
| 沒發光的框 → 白色萬用盤子 | 同一個白框平放在桌面上，放食物就是一盤菜 | 原版物品框架，食物還在 | 可行，基岩版的框可以放在地板與天花板上。盤子是方的 |
| 發光物品展示框 → 螢幕 | 發光物品框架（`glow_frame`）整種換成黑色窄邊框，裡面放 Image map 做的地圖畫 | 發光框裡的地圖畫，仍是一幅會亮的畫 | 很適合：發光框裡的東西不受環境光影響，晚上也是亮的，畫面內容可以用 Image map 自由換 |
| 螢光石 → 更好看的燈飾 | 整種換材質 | 螢光石 | 可行。形狀是完整的一格，適合做燈板、燈箱 |
| 俊光體 → 更好看的燈飾 | 菌光體（`shroomlight`）整種換材質 | 菌光體 | 可行（俊光體是指菌光體還是蛙光體，待確認） |
| 烽火台 → 更好看的燈飾 | 整種換材質，底座、外殼、核心分開換，不動到黑曜石與玻璃 | 烽火台 | 可行。形狀固定是「玻璃外殼包一個核心」，很適合做燈 |
| 漏斗 → 小便斗 | 只能整種換（所有漏斗都變白瓷） | 漏斗 | 漏斗只有一種，沒有其他版本可以當載體，做不到「點了才變」。世界裡的漏斗沒有其他用途的話，整種換最簡單 |
| 畫 → 固定幾張廣告 | 每一幅畫的圖案個別替換 | 原版的畫 | 可行。放畫時遊戲會在放得下的尺寸中隨機挑圖案（新版能不能指定圖案，待確認），所以同一種尺寸的圖案最好做成同一類東西 |
| 畫（一格高）→ 電腦螢幕 | 1×1 的圖案全部做成電腦螢幕（不同畫面），隨機到哪一幅都是螢幕 | 原版的畫 | 可行。原版 1×1 的畫至少有 7 幅 |
| 增加 NPC 的皮膚 | 用原版的 NPC（`/summon npc`），資源包替換它的皮膚 | 原版 NPC 的皮膚，仍然是人 | 可行，也解決了拔掉後怎麼顯示的問題。原版 NPC 有 60 種皮膚可以替換，分成科學家、老師、建築工人、農夫、商人等職業；按職業對應替換，拔掉後也還是同一種職業。NPC 不會走動，可以設定對話 |

## 5. 魔法棒

行為包只放腳本，不新增任何自訂方塊、物品或實體。以下是提案，狀態待決定。

- 用原版物品當魔法棒，拔掉行為包後物品不會消失，只是變回普通物品
- 點到某一類的原版方塊，就換成這一類的下一個載體（例如任何門 → 玻璃門 → 淺灰門 → 白色門 → 玻璃門…）
- 保留方向、開關、上下等狀態；門的上下兩格一起換
- 判斷「確實是那類東西」：用方塊 ID 判斷，例如所有的門、所有的地板門、四種軌道
- 點擊時取消原本的互動（不會順便開門、不會打開漏斗）

## 6. 開發方式

以下是提案，狀態待決定。

- **原始檔放在這個 repo**：資源包與行為包各一個資料夾（例如 `addon/resource_pack/`、`addon/behavior_pack/`），每加一個東西就 commit，修改紀錄都留著
- **開發用資料夾**：用 Windows 的目錄連結（junction），把 repo 裡的資料夾連到遊戲的 `development_resource_packs` 與 `development_behavior_packs`。放在開發用資料夾的包不會被遊戲快取，改完材質重新進入世界就生效，不用每次改版本號；腳本可以用 `/reload` 重新載入。GDK 版的資料夾位置待確認（UWP 版在 `...\LocalState\games\com.mojang\` 底下）
- **只掛在這個世界上**：因為換材質是整種一起換，附加內容只套用在 Asuka City 的世界，不全域啟用，其他世界不受影響
- **和 Clear Craft 疊加**：自製的資源包要排在 Clear Craft 上面，載體的材質才會用自製的版本；材質的解析度配合 Clear Craft，風格才一致
- **先在副本上測試**：新東西先在世界副本上試，穩定後才套用到正式世界
- **封存**：穩定的版本打包成 `.mcaddon` 存一份，換電腦或備份時用
- **工具**：材質用像素繪圖軟體畫；之後如果要做立體模型（例如立體鐵軌）才需要 Blockbench

## 待決定事項

1. 「俊光體」是指菌光體（一種），還是蛙光體（三種顏色：赭黃、蒼翠、珠紫）。如果是蛙光體，三種顏色可以做三種燈，用魔法棒互換
2. 確認載體：以下原版方塊，世界裡有沒有其他用途
   - 漏斗
   - 普通軌道、觸發軌道
   - 上蠟的銅門、上蠟的銅地板門
   - 一般物品框架（例如掛地圖畫）
   - 畫
3. 銅門與銅地板門的第 4 種載體要做什麼（例如深灰、木紋），或先保留
4. 特色鐵軌的比例：原版軌道只有 1 格寬，相當於約 1 公尺的軌距；照[比例尺](scale.md)的微觀放大原則，主線鐵路的軌距應該在 2 格左右。特色鐵軌是要用在主線，還是用在遊樂園小火車、港口或工地的輕便鐵道
5. 立體鐵軌要不要用自訂實體做（只做短距離展示）
6. 魔法棒用哪一個原版物品（例如木棍、旋風棒），要不要用鐵砧命名後才生效，避免誤觸
7. 點擊時的循環順序，以及要不要能換回普通的門（例如蹲下點擊換回鐵門）
8. 廣告與螢幕畫面的內容，可參考[建造清單](build-checklist.md#商店品牌)的品牌
9. NPC 要做哪些人物
10. 附加內容的名稱
11. 開發方式是否照第 6 節
