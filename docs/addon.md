# 附加內容開發

記錄專門為這個世界製作的附加內容（資源包＋行為包）：目標、做法、基岩版的技術限制與構想清單。

> 技術面的說明以 2026 年 10 月的基岩版（1.26.60 前後）為準，標記「待實測」的要在遊戲裡確認。Claude 提出的做法在作者同意前都是「待決定」，選項整理在最後的[待決定事項](#待決定事項)。

---

## 1. 目標與方向

### 目標（已定）

- 做一套專門給這個世界用的附加內容，資源包與行為包一體
- 想到什麼、需要什麼才加，會一直持續添加
- 不能違反[可拔除原則](technical.md#2-建造原則原汁原味)：拔掉之後不影響體驗，放了錦上添花
- 作者最初的構想：原本是「某類」東西的原版方塊，判斷確實是那類東西，用魔法棒點擊才變成自製的樣子；拔掉附加內容後，它還是原本那類的原版方塊。例如對漏斗點擊會變成小便斗，拔掉後還是漏斗

### 作者的顧慮：拔掉後的外觀

第一版提案是「載體方塊」（見[曾考慮的做法](#曾考慮的做法載體方塊)）：例如玻璃地板門其實是上蠟的銅地板門，拔掉附加內容就顯示成銅地板門。作者指出這樣拔掉後外觀差太多，一樣違反原則。

原版本來就顯示不出玻璃門，任何新外觀拔掉後都一定會變樣，差別只在「變成什麼」。載體方塊的問題是退路被載體綁死，不是作者在原版時會選的東西。

### 雙版本（作者提出，暫定）

- 主要在**附加內容版**上建造
- 發布時，用轉換程式找出整張地圖的自製方塊，換成指定的原版方塊，輸出**原味版**
- 可拔除原則的意義跟著改變：主世界可以依賴附加內容，但隨時都要能轉出完整的原味版（待作者確認，確認後更新[技術文檔](technical.md)與 `CLAUDE.md` 的建造原則）

就像程式的原始碼與編譯產物：附加內容版是唯一的原始版本，原味版是轉換出來的，不另外維護。

**原味版對照的準則（Claude 提案，待決定）**：原味版的樣子，等於只用原版時本來會怎麼蓋。銅門不是作者在原版會拿來當玻璃門的東西，所以不合格；原版 NPC 的皮膚是原版裡放人物的唯一方式，所以合格。

## 2. 做法（提案，待決定）

### 三種東西分開處理

| 類型 | 例子 | 原味版怎麼來 |
| --- | --- | --- |
| 自製方塊（行為包＋資源包） | 門、地板門、傳送履帶、鐵軌、小便斗、燈具 | 轉換程式換成對照的原版方塊 |
| 原版東西換材質（只用資源包） | 物品框架、發光物品框架、畫、NPC 皮膚 | 不用轉換：拿掉資源包就是原版的樣子，而且正好是原版裡本來會用的東西 |
| 原版功能 | Image map 做的地圖畫 | 兩個版本完全一樣 |

### 對照表

每一種自製方塊都要登記一個原版對照（包含方向、開關等狀態怎麼對應），寫成一個檔案放在 repo 裡。轉換程式、魔法棒、這份文件都以這張表為準。

**規則：沒有登記對照的自製方塊，不能放進世界。** 對照在做出方塊的當下就決定，不要等到發布時才回頭想。

### 轉換程式

- 在遊戲外處理存檔的**副本**，主世界不動
- 遊戲內的腳本只能讀寫已載入的區塊，8000 × 8000 格的地圖不適合在遊戲裡逐格掃描
- 基岩版的存檔把每 16 × 16 × 16 格的區段存成「調色盤＋索引」：區段裡用到哪幾種方塊列在調色盤，每一格只記編號。所以只要把調色盤裡的自製方塊換成對照的原版方塊就好，不用逐格處理，整張地圖也很快；用結構方塊、`/fill` 放的方塊一樣抓得到
- 遇到對照表沒有的自製方塊就停下來報錯，避免漏掉的方塊在原味版變成未知方塊
- 對照到有方塊實體的原版方塊（例如漏斗有物品欄）時，要一併補上方塊實體的資料（待實測）
- 工具：自己寫（放在這個 repo），或用作者用過的 Amulet（對新版存檔的支援程度待確認）
- **不要等到發布才寫**：附加內容哪天壞掉時，它是退路。建議和[備份](technical.md#6-存檔與備份)一起跑，每次確認轉出來的原味版打得開、沒有未知方塊

### 魔法棒（選用）

- 自製方塊可以直接從物品欄拿出來放，魔法棒不是必要的
- 用途：把世界裡已經蓋好的原版門、軌道、漏斗，原地換成自製方塊，保留方向與開關
- 可以把點擊前是什麼方塊記在自製方塊的狀態裡，轉換時就還原成點擊前的方塊（例如原本是杉木門就還原成杉木門），正好實現作者最初「拔掉後還是漏斗」的構想；直接從物品欄放的，用對照表的預設值
- 用原版物品當魔法棒，拔掉行為包後只是變回普通物品

### 風險

| 風險 | 對策 |
| --- | --- |
| 遊戲自動更新後附加內容壞掉，主世界的自製方塊變成未知方塊 | 已知的行為是資料會保留、附加內容修好後恢復（待實測，要最先測）；大更新前先備份；只用穩定版的功能，不開實驗性功能 |
| 自製物品或實體放進世界（例如放進箱子、物品框架） | 原則上世界裡只放自製方塊，不放自製物品與實體 |
| 結構方塊存起來的結構裡有自製方塊 | 結構只當快取用（見[技術文檔第 5 節](technical.md#5-結構方塊)），原味版不需要 |

## 3. 基岩版的技術限制

| 項目 | 說明 |
| --- | --- |
| 資源包只能換原版方塊的材質，不能換形狀 | 原版方塊的形狀寫死在遊戲裡：門還是門的形狀，漏斗還是漏斗的形狀 |
| 原版方塊換材質是整種一起換 | 同一種方塊沒辦法這格換、那格不換，也不能依方向、開關等狀態換不同的圖 |
| 自製方塊能做的事 | 自己的形狀（模型）、半透明、動畫、發光、方向與開關等狀態。門與地板門的開關、兩格高的門要另外寫腳本 |
| 自製方塊拔掉後 | 變成未知方塊，自製物品與實體會消失 |
| 腳本 | 只用穩定版的 Script API，不用需要開啟實驗性功能（Beta API）的部分，見[技術文檔第 4 節](technical.md#實驗性功能事件)的教訓 |

查原版的材質檔名、方塊狀態時，以 Mojang 官方公開的原版資源包與行為包為準：<https://github.com/Mojang/bedrock-samples>

## 4. 構想清單

構想是作者提出的；做法與原味版對照是 Claude 的提案，狀態都是待決定。

| 構想 | 附加內容版 | 原味版對照（建議） | 備註 |
| --- | --- | --- | --- |
| 玻璃地板門 | 自製方塊 | 鐵地板門 | 可以做半透明。要能開關需寫腳本 |
| 淺灰、白色地板門 | 自製方塊 | 鐵地板門、樺木地板門 | 先做淺灰、白兩色 |
| 玻璃門 | 自製方塊（上下兩格） | 鐵門 | 門最費工：兩格高與開關都要腳本 |
| 淺灰、白色門 | 自製方塊（上下兩格） | 鐵門、樺木門 | 廁所隔間門用淺灰 |
| 傳送履帶 | 自製方塊，會動的動畫 | 觸發軌道 | 可以做彎道，行李轉盤做得出來 |
| 更立體、更真實的特色鐵軌 | 自製方塊，真正立體 | 依原版時的鐵軌蓋法而定 | 軌距可以照[比例尺](scale.md)做成 2 格左右，不受原版軌道 1 格寬的限制 |
| 小便斗 | 自製方塊（小便斗的形狀） | 漏斗 | 作者最初的例子 |
| 更好看的燈飾 | 自製燈具（吸頂燈、燈管、吊燈等形狀） | 原版時本來會用的光源 | 原本想換材質的螢光石、菌光體、烽火台就不用犧牲，維持原樣 |
| 白色的物品展示框 | 物品框架整種換成白色 | 原版物品框架 | 已經放著地圖畫的一般框也會一起變白 |
| 白色萬用盤子 | 同一個白框平放在桌面上，放進食物 | 原版物品框架，食物還在 | 盤子要能放任意食物，只有物品框架做得到，所以不做成自製方塊。盤子是方的 |
| 螢幕 | 發光物品框架整種換成黑色窄邊框，裡面放 Image map 做的地圖畫 | 原版發光框裡的地圖畫，仍是一幅會亮的畫 | 發光框裡的東西不受環境光影響，晚上也是亮的 |
| 固定幾張廣告 | 畫的圖案個別換成廣告；或用 Image map 的地圖畫 | 原版的畫；地圖畫則兩版一樣 | 放畫時遊戲會在放得下的尺寸中隨機挑圖案（新版能不能指定待確認），同一種尺寸的圖案最好做成同一類東西 |
| 電腦螢幕 | 一格高的畫換成螢幕；或做成有底座的立體自製方塊 | 原版的畫；自製方塊的對照待決定 | 原版 1×1 的畫至少有 7 幅，全部做成螢幕的話，隨機到哪一幅都是螢幕 |
| NPC 皮膚 | 原版 NPC（`/summon npc`）的皮膚換掉 | 原版 NPC 的皮膚 | 原版有 60 種皮膚可以換，分成科學家、老師、建築工人、農夫、商人等職業；按職業對應替換，原味版也還是同一種職業。NPC 不會走動，可以設定對話 |

## 5. 開發方式（提案，待決定）

- **原始檔放在這個 repo**：資源包、行為包、對照表、轉換程式都放在 repo，每加一個東西就 commit，修改紀錄都留著
- **開發用資料夾**：用 Windows 的目錄連結（junction），把 repo 裡的資料夾連到遊戲的 `development_resource_packs` 與 `development_behavior_packs`。放在開發用資料夾的包不會被遊戲快取，改完重新進入世界就生效，不用每次改版本號；腳本可以用 `/reload` 重新載入。GDK 版的資料夾位置待確認（UWP 版在 `...\LocalState\games\com.mojang\` 底下）
- **只掛在這個世界上**：不全域啟用，其他世界不受影響
- **和 Clear Craft 疊加**：自製的資源包要排在 Clear Craft 上面；材質的解析度配合 Clear Craft，風格才一致
- **先在副本上測試**：新東西先在世界副本上試，穩定後才套用到正式世界
- **封存**：穩定的版本打包成 `.mcaddon` 存一份，換電腦或備份時用
- **工具**：材質用像素繪圖軟體畫；自製方塊的形狀用 Blockbench 做

## 曾考慮的做法：載體方塊

每一種自製外觀配一種平常用不到的原版方塊當「載體」，資源包只換載體的材質，魔法棒把點到的方塊換成載體。例如上蠟的銅地板門在原版和未上蠟的長得一樣，改掉也不損失原版外觀，可以當玻璃地板門的載體。

- 優點：主世界不依賴附加內容，拔掉後不會出現未知方塊，也不需要轉換程式
- 缺點：拔掉後顯示成載體（例如銅門），外觀差太多；只能換材質，做不出新形狀；原版方塊換材質是整種一起換
- 結果：作者認為拔掉後的外觀違反原則，不採用

也可以「載體方塊＋轉換程式」並用，原味版照樣換成作者指定的方塊，但仍然做不出新形狀，好處只剩附加內容壞掉時不會出現未知方塊。
